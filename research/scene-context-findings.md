## Why this boundary matters

The isolated `SCREEN-AND-STORE` call stops at an unbound `MPLAN`, while the
normal startup path binds a `PLAN` before `RPARSE` and later reaches
`PREP-LINE` and `STORE-IN-FILE`. The same focused trace records a meaningful
state transition without claiming why it happens:

| Checkpoint | Plan/index state | Brush/map state |
|---|---|---|
| `MASTER-PLAN` entry | `MPLAN`, `PREFS`, `SDEX`, `FIGDEX`, `FILL-MAP` are `NIL`; `RGB-MAP` is `T` | pre-plan context |
| `RPARSE` entry | `MPLAN` is `PLAN`; `SDEX` and `FIGDEX` are `FIXNUM` | `FILL-MAP` is `(ARRAY (UNSIGNED-BYTE 4) (320 480))`; `RGB-MAP` bound |
| `PREP-LINE` entry | plan and indexes remain bound | `BRUSH`, `FILL-MAP`, `RPLANE`, and `RGB-MAP` bound |
| first `STORE-IN-FILE` | `MPLAN` remains `PLAN`; indexes remain `FIXNUM` | `FILL-MAP` remains 320×480; `RGB-MAP` and `BRUSH` are `NIL` |

All four rows come from the normalized run `34099250163`; they are not
stitched together from separate executions.

## Controlled writer-boundary follow-up

The optional `writer-seed-1234` mode adds transparent wrappers for the real
`PREP-LINE` and `STORE-IN-FILE` calls to the same seeded startup. Two fresh
runs produced byte-identical seven-snapshot reports (SHA-256
`3c142146407a3d7bcb82f58147a832f71bb0a00324dcf246da9b12655c63ce1f`)
and the same complete AA0 SHA-256 as the simpler seed-1234 control. Thus these
extra wrappers did not change this painting's output bytes.

The chronological order is: first `DRAW-CFORM`, first `STORE-IN-FILE` entry
and exit, outermost `RPARSE` return, first `PREP-LINE` entry and exit, then
first `SCREEN-AND-STORE` entry. The first writer call receives `VECTOR`,
`:PTA`/`:PTB` values of type `VISPT`, and `:REDRAW T`. Its tracked `RGB-MAP`
is `NIL`, while `BRUSH` and `RPLANE` are unbound. The first line-preparation
call receives `NIL` and integer `5`; by then `RGB-MAP` is a nonempty capped
list of `AARGB` objects, `BRUSH` is a `PAINT-BRUSH`, and `RPLANE` is 79. The
15 tracked binding summaries are unchanged between entry and exit for each
first call. That observation does not exclude changes to untracked state,
streams, or the map's contents.

The sanitized report is
[`scene-state-local-windows10-writer-seed1234-20260926.txt`](introspection/evidence/scene-state-local-windows10-writer-seed1234-20260926.txt).
These are calls from distinct phases, so their differing states do not by
themselves establish the rule that changes the colour or brush state. The next
probe should capture a verified state mutation or reader inside the actual
caller path before changing the clean-room scene algorithm.

## Integrated writer stream and formatter correction

The `writer-stream-seed-1234` companion read only the two naturally passed
`VISPT` values and queried the existing `*TEMP*` output stream's position at
the first real `STORE-IN-FILE` call. Two fresh runs produced the same
25,951-byte sanitized report (SHA-256
`a2f17602ba33d0ac1b80544c1a70c0ae657c60dad9110c075f9ce43b21e8b415`)
and the same complete AA0 SHA-256 as the other seed-1234 controls. The report
is retained as
[`scene-state-local-windows10-writer-stream-seed1234-20260926.txt`](introspection/evidence/scene-state-local-windows10-writer-stream-seed1234-20260926.txt).

The natural call is `VECTOR` with `:REDRAW T`. `PTA` has
`X=106.91827677510554`, `Y=384.1616650397512`, `VIS=1`; `PTB` has
`X=109.11479859934074`, `Y=385.81143739727474`, `VIS=1`. `*TEMP*` is an
output file stream at both boundaries and its position advances from 0 to 36.
The first 36 bytes of captured `image` are exactly:

```text
am 106.92 384.16\r\n
ad 109.11 385.81\r\n
```

The complete 124,575-byte `image` file equals the complete AA0 file's suffix
starting at byte 2381; this equality held in both runs. `image` is therefore
the command stream for this seeded painting, while AA0 prepends 2,381 bytes of
dimensions and colour data. The `image` and AA0 files stay in ignored local
captures; the sanitized report and a
[`bounded verification record`](introspection/evidence/writer-image-link-local-windows10-seed1234-20260926.json)
are retained. The comparison can be reproduced with
[`verify-writer-image-suffix.mjs`](tools/verify-writer-image-suffix.mjs) and the
local runner's three captured files.
The first call's positions align with this slice, so its natural output is
measured without replacing `PLOT` or the writer stream.

The prior JS two-decimal formatter truncated every value. That failed this
natural call at `106.918...`: it produced `106.91` where AARON produced
`106.92`. `AaronStrokeWriter` now rounds to the nearest cent with observed
half-cent ties toward zero; its integrated first-vector fixture and all 240
isolated VECTOR/FILL cases pass. This supports the tested formatter cases, not
all possible floating-point boundaries or the unmeasured previous-point state.

The follow-up `writer-sequence-seed-1234` mode captured 64 consecutive natural
`STORE-IN-FILE` calls from a painting with 28,075 writer calls. Two fresh runs
have identical 51,563-byte sanitized reports (SHA-256
`d0332c2b432636eeb8f4830b162b4dd7e7f803cd2b28e30cf69b7fd23990d006`)
and identical 33,787-byte bounded fixtures (SHA-256
`cc0f62f2a25a994d392435fc94addadefb16a3177f72e06299af83230fcb330a`).
The complete AA0 hash remains the seed-1234 control hash. The first 64 calls
are all successful `VECTOR` calls with `:REDRAW T`; their stream intervals are
contiguous from byte 0 through byte 1224. Four intervals contain a move and
draw; the other 60 contain a draw only. Two calls have `VIS=0` on `PTA`, both
among the move intervals. These observations do not establish that visibility
itself caused the move.

The normalized
[`writer sequence fixture`](introspection/evidence/writer-sequence-local-windows10-seed1234-20260926.json)
contains the original point values and exact per-call bytes; the
[`sanitized report`](introspection/evidence/scene-state-local-windows10-writer-sequence-seed1234-20260926.txt)
contains paired natural call events and stream positions. The
[`summarizer`](tools/summarize-writer-sequence.mjs) verifies every slice against
the temporary `image` file and checks that it is the final AA0 suffix. With a
distinct sentinel for the unknown first previous point, the JS writer matches
all 64 original slices byte for byte. From call 1 onward, its previous point
comes from the preceding captured VECTOR. This extends integrated file
emission evidence across multiple line continuations and breaks; it does not
yet validate the unobserved prior state, `PLOT`'s screen effects, or the other
28,011 writer calls in this painting.

The later `writer-windows-seed-1234` probe resolves the prior-state gap and
samples the full painting's writer selector families. Runs
`writer-windows-seed-1234-g` and `writer-windows-seed-1234-h` produced identical
390,307-byte sanitized reports (SHA-256
`03291fec7f6205f411d15f16113e52af854565bd21a11dd7c3a9ac279e82f898`),
identical 124,575-byte `image` streams (SHA-256
`42189c06d4383884268ab1b4935a015b4fc70300869a195a7511044f18897881`),
and the same seed-1234 complete AA0 hash. The report counts all 28,075 natural
calls and records 299 short windows with selector, bounded arguments, stream
positions, the original `PREV-STORED-PT` before and after each call, and the
native `?FILE-SIZE?` binding. Its first previous point is `(0,0)`, and all
sampled calls use `?FILE-SIZE?=SMALL`. It captures all nine selectors used in this
scene: `VECTOR`, `COLOR`, `BRUSH`, `AARGB`, `MOVE-TO`, `DRAW-TO`, `HUE`, `FILL`,
and `END`. `HUE` and `AARGB` both emit `nc <index>`; `COLOR` emits `color`;
`BRUSH` emits `nb <width>`. The `TRIPT` move/draw and `TWOPT` fill points were
read through the same `X`/`Y` accessors referenced by their original methods.
`END` succeeds but closes the stream, so a position query at its exit reports

The [`windowed fixture`](introspection/evidence/writer-windows-local-windows10-seed1234-20260926.json)
links each sampled call to its exact output bytes, verified against the AA0
suffix. A byte-and-state regression test reproduces all 299 calls with the JS
writer in `small` hop mode. This establishes a bounded file-writer result for
one painting, not complete JS generator or screen parity.

## Evidence limits

- A compiled constant reference does not prove a call, read/write direction,
  or execution order.
- A PLL indexed name does not prove package ownership, class layout, slot
  layout, or a function boundary.
- A missing value at one checkpoint does not prove the binding is absent at
  another point in the generator.
- The dossier must not manufacture a `PLAN`, merge independent runs into one
  timeline, or promote a future observation to an artistic rule without a
  controlled comparison.
