## Why this boundary matters

The isolated `SCREEN-AND-STORE` call stops at an unbound `MPLAN`, while the
normal startup path binds a `PLAN` before `RPARSE` and later reaches
`PREP-LINE` and `STORE-IN-FILE`. The same focused trace records a meaningful
state transition without claiming why it happens:

| Checkpoint | Plan/index state | Brush/map state |
|---|---|---|
| `MASTER-PLAN` entry | `MPLAN`, `PREFS`, `SDEX`, `FIGDEX`, `FILL-MAP` are `NIL`; `RGB-MAP` is `T` | pre-plan context |
| `RPARSE` entry | `MPLAN` is `PLAN`; `SDEX` and `FIGDEX` are `FIXNUM` | `FILL-MAP` is `(ARRAY (UNSIGNED-BYTE 4) (320 480))`; `RGB-MAP` bound |
| `PREP-LINE` entry | plan and indexes remain bound | `BRUSH`, `FILL-MAP`, `RPLANE`, and `RGB-MAP` bound |
| first `STORE-IN-FILE` | `MPLAN` remains `PLAN`; indexes remain `FIXNUM` | `FILL-MAP` remains 320×480; `RGB-MAP` and `BRUSH` are `NIL` |

All four rows come from the normalized run `34099250163`; they are not
stitched together from separate executions.

## Package-qualified candidates

The dossier joins exact package/name references from the retained compiled
constant report and generic-method report with the static PLL name index and
the four runtime checkpoints. All 16 selected names are present in the
complete PLL’s indexed string table. That establishes names and offsets only;
it does not establish package ownership from the image alone.

The highest-priority future observations are:

1. Read-only type/value summaries for `COMMON-GRAPHICS-USER::MPLAN`,
   `SCRIPT`, `SDEX`, `FIGDEX`, `CFLIST`, and `IDLIST` immediately after
   `RPARSE`, without constructing a substitute plan.
2. A single bounded `SCREEN-AND-STORE` boundary that snapshots the
   package-qualified `BRUSH`, `RPLANE`, `RGB-MAP`, `COLORDEX`, and `PREFS`
   bindings before and after the existing downstream stubs.
3. If those values are live objects, inspect only documented type/class names
   and safe scalar/list summaries first; defer slot traversal until a separate
   probe proves the accessor path.

This is a target-selection checklist, not a recovered scene algorithm.

## Evidence limits

- A compiled constant reference does not prove a call, read/write direction,
  or execution order.
- A PLL indexed name does not prove package ownership, class layout, slot
  layout, or a function boundary.
- A missing value at one checkpoint does not prove the binding is absent at
  another point in the generator.
- The dossier must not manufacture a `PLAN`, merge independent runs into one
  timeline, or promote a future observation to an artistic rule without a
  controlled comparison.
